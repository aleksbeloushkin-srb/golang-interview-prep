# Практикум недель 1–7 и 10 — эталоны и тесты

Источник кода для раздела `#/practice` (данные — `data/practice.js`; `scripts/check-content.mjs` сверяет их с файлами здесь). В каждом каталоге: эталон `<task>.go`, тесты `<task>_test.go`, заготовка `starter.go.txt`.

```bash
go vet ./... && go test -race -count=1 ./...
```

Проверено Go 1.24.7 и Go 1.27.3 (linux/amd64, `-race`). Тесты отлавливают типичные ошибки (проверено мутациями: пул без ограничения, воркер без отмены, `close` в каждом отправителе, nil-вход в fan-in, счётчик без блокировки, кеш без копий, нарушенный инвариант; для недель 1–3 — `%v` вместо `%w` в account и validation, `LineError` без `Unwrap`, знак через `%` в money, ресивер-значение у Deposit, Transfer без перевода, `float64` в money, произвольный текст `Error()`, граница возраста `< 19`, проверка age раньше email).

Недели 1–3 (нумерация v91): `money` (W1-1), `account` (W1-2), `validation` (W2-1), `deferpanic` (W2-2, W2-3), `removeslice` (W3-1), `generics` (W3-2, W3-3), `txsum` (W3-4). Неделя 4: `workerpool`, `pipeline`, `fanin`, `counter`, `safecache` (W4-1…W4-5). Неделя 5: `ratelimit` (W5-2), `shutdown` (W5-3), `leak` (W5-4), `escape` (W5-5), `txprof` (W5-6, заготовка — решение W3-4; в тесте осталось прежнее «W4-6» — тесты хранит бэкенд); W5-1 `parallelfetch` — в соседнем модуле `../practice-errgroup`, потому что ему нужен `golang.org/x/sync`.

Особенности недели 5: тест `leak` намеренно оставляет две горутины `FirstLeaky` до конца тестового бинарника — это демонстрация утечки; `escape` и `txprof` проверяют число аллокаций через `testing.AllocsPerRun` (проходит и с `-race` на Go 1.24.7); строки `-gcflags=-m` в задаче W5-5 сняты с Go 1.24.7.

Неделя 7: `transfers` (W7-1: мьютекс на счёт, блокировки по возрастанию ID, инвариант суммы под 100 горутинами; дедлок ловится таймаутом теста), `idempotency` (W7-2: хранилище ключей и HTTP-обработчик — 400/422/409, сохранённый ответ, сбой не сохраняется), `outbox` (W7-3: событие в той же «транзакции», relay через ненадёжный брокер — потеря отправки и потеря подтверждения, порядок первого появления, остановка по ctx; идемпотентный потребитель). Мутации пойманы: блокировки в порядке запроса, проверка баланса до блокировки, Total без общего снимка, «проверить, потом занять ключ», fn под блокировкой, ключ не освобождается после ошибки, отпечаток сырого тела, сохранение 500, отметка до Publish, continue вместо остановки пачки, Publish под блокировкой базы, потребитель без дедупликации, Run без ctx.Done().
