# Горутины, стеки и планировщик — проверочные примеры порции 14

Из каталога этого модуля:

```sh
go test -race -count=1 -timeout=45s -v ./...
go vet ./...
go run ./c1
go run ./c3
go run ./c4
go run ./c5
go run ./c7
go run ./c8
```

Исполнено **Go 1.26.1 darwin/arm64**. Директива `go 1.17` фиксирует минимальную языковую/API-базу примеров; это не запуск старого toolchain. Внешних зависимостей нет. Семь файлов `example.go` точно соответствуют полям `code` карточек с точностью до конечного перевода строки. c10 — пакет с функцией и тестами, а не standalone main. c9/c11 — явно подписанные модели очередей, не Go-программы.

| Карточка | Ожидаемое наблюдение |
|---|---|
| c1 | `work finished`; main ждёт сигнал завершения |
| c3 | `1 2`: аргумент вычислен у вызывающего |
| c4 | Счётчики stack spans/goroutines; числа зависят от процесса |
| c5 | `42 2080`: указатель и данные вложенных вызовов сохраняют смысл |
| c7 | Текущая настройка GOMAXPROCS; число зависит от окружения |
| c8 | `context canceled`: приложение само проверило отмену |
| c10 | Callback допущен в пределах общего лимитера; слот возвращается при завершении |

Шесть тест-функций и внутренние случаи проверяют глубины 0/1/64/256, небольшие суммы/отмену, ограничение активных callback, завершение всех запущенных задач, отмену при занятой ёмкости, error/panic и поддержанную callback отмену. Каналы задают порядок; Sleep для синхронизации не используется. Timeout тестового процесса ограничивает зависание при регрессии.

Тест указателя не доказывает физическое размещение каждого кадра или момент копирования стека. Тесты лимитера не доказывают точное число OS threads, справедливость допуска и принудительную отмену C. Лимитер создаётся с положительной ёмкостью, разделяется между вызовами и не закрывается. Отмена может совпасть со стартом work: callback должен поддерживать её сам.

После запуска HTTP-сервера и отдельного Chrome согласно [workflow](../../../../VERIFICATION_WORKFLOW_RU.md), из корня репозитория:

```sh
node scripts/browser-smoke.mjs --output /tmp/scheduler-smoke.json
node docs/verification/fixtures/scheduler-browser.mjs --output /tmp/scheduler-browser.json
```

Corpus-сценарий проверяет все карточки, варианты quiz, шаги схем, связи и layout; последовательные карточки переключает настоящей кнопкой «Далее», чтобы не создавать сотни hash-навигаций подряд. 320/390/430/1440 px; удвоение фактических шрифтов у изменённых материалов. Снимки пишутся в `/private/tmp/scheduler-*.png` и требуют просмотра человеком. Сценарий использует отдельный browser context и удаляет его после завершения; сервер и Chrome нужно остановить отдельно.

Фактические результаты и границы — [итоговый отчёт](../../2026-10-27-scheduler-final.json). Новые runtime-факты проверены чтением tagged sources; JavaScript-проверки и Go-примеры не заменяют этого чтения.
