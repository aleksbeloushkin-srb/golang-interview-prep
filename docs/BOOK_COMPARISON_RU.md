# Сайт и книга «Concurrency in Go» (Katherine Cox-Buday, O'Reilly, 2017)

Сравнение определений и объяснений сайта с книгой. Книга написана во времена Go 1.8–1.9, поэтому из неё берём язык, понятия и короткие чек-листы, а не устройство рантайма. Определения книги здесь пересказаны своими словами; в скобках — раздел и страница книги. Текст книги в репозиторий не кладём.

## Главное

- **Что брать.** Словарь (условия Коффмана, livelock, «атомарно относительно чего», join point, confinement) и короткие чек-листы: четыре вопроса «канал или мьютекс», четыре обязанности владельца канала, три способа завершиться для горутины, два условия для fan-out, закон Литтла для очередей. Плюс взгляд на ошибки на границе модуля: неизвестная ошибка, вышедшая наружу, — это баг.
- **Чего не брать.** Всё про рантайм: карточки c3–c11 и диаграммы sim1–sim2 глубже и верны для текущего Go. Модели памяти и happens-before в книге нет, на сайте есть (sim5, шаг 7).

## По понятиям

|---|---|---|---|
| Конкурентность и параллелизм (§ гл. 2, с. 23) | Конкурентность — свойство кода, параллелизм — свойство работающей программы; параллельно ли что-то шло, зависит от окна времени | c1, c7 | Одна строка-опора в c1 |
| Race condition (с. 4) | Код полагается на порядок, который ничто не гарантирует; мысленно поставьте час между двумя строками; Sleep лишь делает ошибку реже | c2 | Оставить c2, добавить «Sleep — не исправление» |
| Data race (с. 4) | Самый частый вид race condition | c2 — точнее книги | Оставить формулировку сайта |
| Атомарность (с. 6) | Неделимость всегда «относительно контекста»; `i++` — три шага; из атомарных шагов не складывается атомарное целое | c2, c20, sim5 | Добавить «атомарно относительно чего?» со ссылками на мьютекс, CAS и транзакцию (c50) |
| Критическая секция (с. 8–10) | Код, которому нужен монопольный доступ; блокировка — лишь договорённость; убрав data race, можно оставить race condition | c2, c15, c21 | Определение и «блокировка — договорённость» |
| Deadlock и условия Коффмана (с. 10–13) | Все ждут всех; четыре условия: взаимное исключение, удержание с ожиданием, нет вытеснения, циклическое ожидание; сломай одно — и deadlock невозможен | c50 (порядок блокировок), sim3, q8, q41; условия не названы | **Добавить**: порядок убирает циклическое ожидание, TryLock/таймаут — удержание с ожиданием |

| Starvation (с. 15–17) | «Жадный» и «вежливый» воркер; заметить по метрикам пропускной способности; касается любого ресурса: CPU, памяти, файлов, соединений | c21, sim8 (режим голодания мьютекса), c8–c11 | Взять пример «жадный/вежливый» и идею метрик в c21 |
| Безопасность API для конкурентности (с. 18) | Документация должна говорить, кто запускает конкурентность, на чём она построена и кто синхронизирует | c1 (владелец и выход) | Чек-лист для ревью кода |
| CSP и «share memory by communicating» (гл. 2) | Модель Хоара; Go поддерживает и каналы, и блокировки как равноправные | только в практикуме | Пословица — в c15 |
| Канал или мьютекс (с. 33–35) | Передаёте владение → канал; защищаете внутреннее состояние типа → мьютекс внутри типа; координируете несколько частей → каналы и select; профилированное горячее место → примитивы | c15: владение против инварианта | **Все четыре вопроса — опорами в c15** |
| Горутина, M:N (с. 37–39) | Сопрограмма без вытеснения, «зелёные потоки» поверх потоков ОС | c1, c3, c7, c8, sim1, sim2 | Оставить сайт: книга устарела |

| WaitGroup (с. 47) | Когда результаты не нужны; Add — вне горутины | c22 | Оставить; у книги нет `wg.Go` (1.25) и errgroup |

## Что добавить — по приоритету

**Высокий**
1. Новая карточка в модуле 3: deadlock, livelock и starvation, условия Коффмана; вопрос в quiz; ссылки на c50 и sim8.
2. c15: четыре вопроса «канал или мьютекс», confinement и неизменяемые копии как третий вариант, пословица Go.
3. c1 и c12: «join point», три способа завершиться, «кто запустил — тот и останавливает».

**Средний**
4. «Атомарно относительно чего?» — строка в подробностях c2 или c20.
5. c13: закон Литтла и «очередь развязывает стадии, но не ускоряет»; вопрос в quiz.
6. Ошибки из горутин: структура «результат + ошибка» против `errgroup.WithContext`.
7. Условия fan-out — в эталон w3-wed-2.
8. c45: hedged requests и причины таймаутов.
9. Верная заметка про `sync.Pool`.

**Низкий:** `sync.Cond` в quiz; or-done/tee/bridge одной задачей практикума; heartbeats в c12; чек-лист документации API в c15.

## Где книга устарела или неверна — не переносить

- Горутины «без вытеснения», «зелёные потоки» (с. 37–39): с Go 1.14 есть асинхронное вытеснение, модель — G на M через P.
- «Go крадёт продолжения» (с. 205): `newproc` ставит в очередь новую горутину, а вызывающая продолжает работать (`runtime/proc.go`), то есть в очередь попадает и крадётся задача; runnext лишь даёт ей приоритет на том же P.
- Блокирующий ввод-вывод как системный вызов (с. 210–211): netpoller не описан; ожидание сети не держит поток (c10).
- `sync.Pool` как пул фиксированного размера или кеш соединений (с. 59–64): неверно.
- «Горутины бесплатны — пулы воркеров не нужны» (с. 35): серверам нужна ограниченная конкурентность (`errgroup.SetLimit`, семафоры).
- Обход ловушки переменной цикла (с. 40–42): не нужен с Go 1.22.
- GOMAXPROCS = число CPU (с. 83): с Go 1.25 учитывает лимиты cgroup и обновляется сам.
- pkg/errors и свои типы со стеком: сейчас `%w`, `errors.Is/As` (1.13), `errors.Join` (1.20).
- done-каналы и `interface{}` повсюду: сейчас context, generics, `chan struct{}`, iter.Seq (1.23).
- Цифры бенчмарков (размер горутины, время переключения, паузы GC «на 1.8») — не цитировать.
- В книге нет: sync.Map (1.9), атомарных типов (1.19), OnceFunc (1.21), `wg.Go` (1.25), errgroup, Cause/AfterFunc/WithoutCancel у context.
