# Разбор входа о запоминаемости и что сделано в v80

Вход — `docs/REVIEW_INPUT_2026-10-31_MEMORY_RU.md` (две части от другой системы, 31 октября). Сверено с сайтом v79 и исходниками Go 1.24.7 / 1.26.1 / 1.27.3; три сверки шли параллельно, каждая — со своим списком правок. Решения пользователя 1 ноября: состояние фишки — явным полем; изменения на шаге — значок «Δ», выделенный цветом.

## Итог по пунктам

| Пункт входа | Решение |
|---|---|
| Приглушать дорожки без изменений (opacity ~0.5) | Не взято, как в v77 (п. 15): падает контраст, «вернуть по наведению» не работает на телефоне, в «неизменённых» дорожках — контекст для predict. **Сделано иначе:** дорожка с изменением получает янтарную рамку; не ставится, если изменилось всё или у панели `hlQuiet` |
| «Δ» вместо слова «изменилось» | **Сделано:** янтарная плашка с тёмной «Δ» (читается и на белых/чёрных дорожках GC), для читалки — скрытое «изменилось». Свои подписи (`hlLabel`, «кандидат» в sim9) остаются словом |
| Цвета фишек по словам в тексте (running / runnable / waiting / sys / danger) | Не по словам (хрупко, v75). Решение пользователя — **явное поле** у фишки; отдельным выпуском на 12 диаграмм. Имя не `state` (занято у дорожек); палитра — по состоянию, а не «успех/авария»: `false` проигравшего CAS — нормальный исход |
| Постоянство расположения дорожек | Принцип верный; отдельно по 12 диаграммам не проверялся — вместе с полем состояния |
| «Формула шага» (18 штук) | **Сделано** новым полем шага `formula` («Шаг коротко: …»), а не в `list.title`: у 83 из 110 списков заголовок уже конкретный, а формула относится к шагу (у sim6/5 две панели). Выводится внутри доски — на шагах с predict открывается вместе с ответом. Из 18 формул 9 верны, 6 неточны, 3 ошибочны — все переписаны (ниже) |
| Hook → Mechanism → Boundary | Уже в `docs/ANSWER_STYLE_RU.md`: первая фраза отвечает, условие — в конце и в опоре. Отдельное поле `hookEN` не брали (v75) |

Под правило «3–4 × 5–7» сейчас подходят 10 карточек из 64. **Сделано:** ориентир в стиле — опора на один вдох, до 10 слов, длиннее 12 разбивать при ревизии карточки (10 таких карточек названы в стиле) |

## Формулы шагов: что исправлено

| Шаг | Во входе | Что не так |
|---|---|---|
| sim5/4 | `LOCK CMPXCHGL … → записать CX → SETEQ` | CX пишется только при равенстве, иначе AX = [BX] (`atomic_amd64.s#Cas`) |
| sim6/5 | «гибридный барьер красит C в серый» | Барьер учитывает старое и новое значение (`mwbbuf.go`), серым C становится не сразу; без `B.Next = nil` угрозы нет |
| sim7/3 | «empty = стоп» | Ключ найден в слоте 2; empty останавливает поиск только при промахе (`getWithKey`) |
| sim2/2, sim2/5 | «~10 мс», «⌈n/2⌉ … на CPU» | Порог ≥ 10 мс (`forcePreemptNS`); в исходнике `n - n/2`; `runqsteal` лишь возвращает G для P2 |
| sim3/2, sim4/4, sim4/5, sim8/5, sim11/2 | — | Пропущены `park_m` и `parkingOnChan`; sudog на каждый case, не на канал; «первый» → «выигравший»; G4 берёт мьютекс «часто», не всегда; условия Коффмана — шаг 3, не 2 |

## Сделано в v80 вне входа (неделя 1)

- **c65 «Чем встраивание отличается от наследования»** (m6, для Java/Kotlin): продвижение полей и методов, «не подтип, нет super», ловушка шаблонного метода и как её обойти; сравнение с `extends` и Kotlin `by`. Попутно найдено изменение Go 1.27: ключом литерала структуры может быть продвинутое поле (`Outer{ID: "7"}`), не через встроенный указатель и при `go 1.27` в go.mod — проверено компиляцией. **q52** — та же ловушка в quiz. Озвучено.
