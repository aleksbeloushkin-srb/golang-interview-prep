# Разбор ревью платформы v82 и плана доработок — что сделано в v83

Вход — `docs/REVIEW_INPUT_2026-11-05_PLATFORM_RU.md` (ревью и план от другой системы, 5 ноября). Каждый пункт сверен с `main` v82 и бэкендом `golang-interview-prep-api`; факты о Go — по исходникам 1.27.3.

## Ревью: итог по пунктам

| Пункт | Решение |
|---|---|
| **M1.** Две вкладки стирают отметки друг друга | **Верно, сделано.** Отметка карточки и задачи плана пишется поверх свежего снимка из хранилища, а не целым объектом из памяти; другая вкладка ловит событие `storage` и обновляет счётчик, статус и галочки. Попытки карточек, проговор и практикум и раньше перечитывали хранилище перед записью — для них угрозы не было |
| **M2.** При конфликте устройств — только «весь сервер» или «весь браузер» | **Верно, сделано.** Новая кнопка «Объединить (рекомендуется)» — слияние по типам (`js/progress-merge.js`): попытки и проговор — без повторов, по дате; отметки плана и решённые задачи — объединение; статус карточки — с устройства, где последняя попытка новее, при равенстве «на повторении»; настройки — этого браузера. Две прежние кнопки теперь говорят, что заменят. Цена объединения: снятая на одном устройстве отметка вернётся — так и написано в панели |
| **M3.** «Сам» = «изучено» навсегда | **Верно, сделано.** Дата следующей проверки выводится из истории попыток: «не ответил» — завтра, «с опорой» — через 2 дня, «сам» подряд — через 4, 8, 16, затем 30 дней (гипотеза, пересмотреть по нагрузке). «Изучено» → «Ответил сам ✓ · следующая проверка dd.mm»; полоса — «ответил сам на последней проверке — N из 72 · к повторению: K». Подборка «На повторение» включает и тех, у кого подошла дата. Кнопка «▶ Продолжить занятие» (на карточках и в плане): до 10 карточек — просроченные, самые давние сначала, затем ещё не проверенные карточки текущей недели плана; позиция переживает перезагрузку |
| **L1.** Перезагрузка сбрасывает подборку | **Верно, сделано.** Модуль, уровень и поиск — в `sessionStorage` (на другие устройства не уходят); карточка по ссылке вне подборки, как и раньше, открывает «Все» |
| **L2.** Смена раздела не меняет заголовок вкладки и фокус | **Верно, сделано.** Заголовок вкладки «Карточки / Диаграммы / База знаний / Шпаргалка / Quiz — Go Interview Prep», фокус — на заголовок раздела (по ссылке на диаграмму или задачу quiz — на её заголовок). Внутри раздела (листание карточек и шагов) фокус не трогается. План и практикум делали это и раньше |
| **L3.** После H фокус на опорах невидим | **Верно, сделано.** Рамка `:focus-visible`; при щелчке мышью её нет |
| **L4.** c21, c55, c56 длиннее цели «49–86 слов» | **Частично.** «49–86» — правило v66; действующее в `docs/ANSWER_STYLE_RU.md` — 70–100 слов. По нему длинный только **c21** (119 → 100 слов); **c56** 101 → 100; **c55** (96) укладывается и не менялся. Переозвучены c21 (46 → 39–42 с) и c56 (40–41 с) |
| **L5.** c22 не говорит о публикации `Once` | **Верно, сделано:** «Once also publishes the result: after Do returns, every caller sees what the initializer wrote» (EN и RU), новая опора; переозвучено. В Go 1.27.3 возврат `f` синхронизируется до возврата любого `once.Do(f)` (модель памяти, раздел Once) |
| **L6.** c21: «покрутится, а потом засыпает» звучит обязательно | **Верно, сделано:** «may spin briefly and retry, and sleeps on the semaphore only if it is still held»; опора «Lock: CAS → brief spin, try again → sleep only if still held». По `lockSlow` в 1.27.3 после спина `Lock` снова пробует CAS и паркуется (`runtime_SemacquireMutex`), только если мьютекс занят |
| DAU Counter | Кандидат в карточку или практикум модуля 3 — в очередь, не дефект |
| Озвучка c57–c64 и c66–c72 | **Сделано** — 15 карточек, короткий ответ и JVM, оба голоса |

## План доработок: итог по этапам

| Этап | Решение |
|---|---|
| Хранилище: без новой БД, прогресс в существующей DynamoDB | **Согласен, так и сделано.** Бэкенд хранит прогресс как непрозрачный JSON с версией (409 при конфликте) и пределом 300 КиБ (`internal/api/api.go`, `MaxProgressBytes`) — новые ключи и поля не требуют ни схемы, ни маршрута. Расписание повторения вообще не хранится отдельно: оно считается из попыток. «Кода бэкенда нет в рабочей копии» — неверно для этой среды: репозиторий `golang-interview-prep-api` здесь есть и сверен |
| Этап 0. Бюджет и фактический счёт | **За пользователем:** к AWS Billing у меня доступа нет, и ключи AWS я не прошу. Шаги — ниже |
| Этап 1. Надёжность прогресса | **Сделано** (M1, M2). Размер записи: попытки ограничены 20 на карточку, проговор — 5 на задачу; текст ответов и аудио не хранятся — до 300 КиБ далеко |
| Этап 2. Очередь повторения без новых AWS-ресурсов | **Сделано** в клиенте (M3). Серверная `NextReview` в Go не нужна: расписание — чистая функция истории попыток, одинаковая на всех устройствах после синхронизации |
| Этап 3. «Продолжить занятие» | **Сделано** (M3); счётчик «новые на этой неделе» — в подписи кнопки |
| Этап 4. Серверная логика | Не нужна сейчас (см. этап 2) |
| Этап 5. Интерфейс и доступность | **Сделано** (L1–L3) |
| Этап 6. Аудио и выпуск | **Сделано**: c21, c22, c56 переозвучены, c57–c64 и c66–c72 озвучены. Прослушивание — за пользователем (`docs/AUDIO_REVIEW_RU.md`) |
| Этап 7. Публичный доступ | Не нужен для личного использования; условия (Cognito в Testing, изоляция runner, лимиты) — в очереди хендоффа |

### Бюджет AWS — что сделать в консоли (5 минут)

1. **Billing → Cost Explorer:** расходы за 30–90 дней по сервисам (Lambda отдельно API и runner, API Gateway, DynamoDB, CloudWatch Logs, ECR, Secrets Manager, Cognito); остаток кредитов и срок Free Plan.
2. **Billing → Budgets → Create budget:** месячный бюджет затрат с уведомлениями на $2 и $5 на свою почту. Бюджет только предупреждает, с задержкой, и не останавливает расходы.
3. **Cost Anomaly Detection:** включить монитор по сервисам.
