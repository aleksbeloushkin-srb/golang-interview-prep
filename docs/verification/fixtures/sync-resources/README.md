# Проверка синхронизации и ресурсов — порция 13

Из корня этого модуля:

```bash
go test -race -count=1 -timeout=45s -v ./...
go vet ./...
```

Исполнено на Go 1.26.1 darwin/arm64. `go 1.25.0` задаёт минимальную версию для WaitGroup.Go/synctest, а не свидетельствует о прогоне на Go 1.25. `x/sync v0.20.0` — явная зависимость только проверочного модуля; сайт остаётся без внешних runtime-зависимостей. История WaitGroup/Mutex сверена с тегами Go 1.17/1.25.0/1.26.1. Старые toolchain не исполнялись.

Три программы c15/c21/c22 и исходники/исправления семи quiz совпадают с 17 блоками кода сайта. Горутины примеров используют явное владение индексами и ожидание; они не являются готовым ограниченным worker pool.

| Команда | Ожидаемый результат |
|---|---|
| `go run ./c15` | `true false` |
| `go run ./c21` | `false`, затем `acquired` |
| `go run ./c22` | `[42 42]` |
| `go run ./q7` | `working`, успешный выход |
| `go run ./q8` | `1`, успешный выход |
| `go run ./testdata/q7` | Намеренный fatal deadlock после вызова worker |
| `go run ./testdata/q8` | Намеренный fatal deadlock повторного Lock |
| `go vet ./testdata/q7` | Намеренная диагностика copylocks |
| `go test -race -count=1 ./testdata/q12` | Намеренная ошибка DATA RACE; воспроизведена, но отсутствие диагностики в отдельном запуске не доказывает безопасность |

Негативные программы запускаются отдельно; каталог testdata не входит в обход `./...`. Функции ошибочных q10/q16/q19 импортируются целевыми тестами для проверки контракта и корректного завершения. Исправленные функции находятся в q10/q12/q13/q16/q19.

Проверки используют настоящий `httptest.Server`, чтобы отмена контекста происходила при возврате handler сервером. Для SQL используется настоящий `database/sql` и управляемый driver: тестируются удержание Rows, ожидание пула, отмена, EOF, ранний break, ошибки Query/Scan/Next/Close и сохранение двух ошибок. PostgreSQL, сеть БД, SQL-диалект и согласованность пагинации не проверяются. В тесте отказа пула намеренно достаточно двух соединений: важен предел пула, не магическое число 25.

Проверка q13 подтверждает единственное создание в исправлении. Отдельный тест явно задаёт интерливинг двух устаревших проверок без data race: это модель плохого алгоритма, а не обещание конкретного расписания исходной функции. Тесты не доказывают временные границы Mutex, производительность или все возможные исполнения.

После запуска HTTP-сервера и Chrome по VERIFICATION_WORKFLOW_RU.md, из корня репозитория:

```bash
node scripts/browser-smoke.mjs --output /tmp/sync-smoke.json
node docs/verification/fixtures/sync-resources-browser.mjs --output /tmp/sync-target.json
```

Целевой сценарий проверяет три карточки, семь quiz, исправленные примеры, обратные ссылки, клавиатуру, раскрытые состояния на 320/390/430/1440 px и удвоенные фактические шрифты. Он не заменяет смысловую сверку EN/RU и просмотр изображений. Скриншоты пишет в `/private/tmp/sync-*.png`. Сервер и Chrome после проверки нужно остановить.
