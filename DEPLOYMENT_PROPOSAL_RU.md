**Предложение: вход через Google, база данных и интерактивные задачи на AWS**

28 октября 2026. Черновик для решения пользователя и для Астры. Ничего не развёрнуто. Пошаговый рецепт (аккаунт, Google, CDK, GitHub Actions) — [`AWS_RECIPE_RU.md`](AWS_RECIPE_RU.md). Цены — порядок величин, перед запуском проверить в AWS Pricing Calculator.

## 1. Что хотим получить

1. Вход через Google: прогресс один на телефоне и компьютере.
2. База данных: отметки карточек и плана, история попыток, интервальное повторение на сервере.
3. Интерактивные задачи: написать код на Go в браузере, запустить скрытые тесты, получить результат; затем — задачи code review.
4. Позже: проверка ответов на английском и ревью кода с помощью модели (Amazon Bedrock).

Статический сайт остаётся как есть (GitHub Pages, без сборки). Новое — отдельный API на AWS. Это быстрее всего: ничего не ломаем и можем включать функции по одной.

## 2. Рекомендуемая схема (AWS, serverless, регион eu-north-1)

| Часть | Сервис | Зачем |
|---|---|---|
| Сайт | GitHub Pages (позже можно S3 + CloudFront) | Без изменений |
| Вход | Amazon Cognito: пул пользователей + Google как внешний провайдер | OAuth 2.0 Authorization Code + PKCE прямо из браузера, без секретов в коде сайта |
| API | API Gateway HTTP API + JWT-авторизатор Cognito | Проверка токена без своего кода |
| Логика | AWS Lambda на Go (arm64, provided.al2023) | Один бинарник на функцию; холодный старт десятки миллисекунд |
| Данные | DynamoDB, режим on-demand | Платим за запросы; для одного-пяти пользователей почти бесплатно |
| Запуск кода | Отдельная Lambda из контейнерного образа с Go toolchain | Изоляция Firecracker, лимиты времени и памяти |
| Инфраструктура | AWS CDK на Go, деплой из GitHub Actions | В новом формате AWS OIDC-провайдер создать нельзя (`iam:*Provider*` запрещён), поэтому ключ IAM-пользователя, который может только принять роли CDK; подробно — `AWS_RECIPE_RU.md`, 6.1 |
| Наблюдаемость | CloudWatch Logs, бюджет и оповещение AWS Budgets | Контроль расходов с первого дня |

Аккаунт создан в новом формате AWS (проект, Builder ID, регион Stockholm `eu-north-1` без выбора, Free plan до 28.04.2027). До окончания Free plan — переход на Paid с лимитом расходов проекта; кредиты до $200. Cognito: 10 000 активных пользователей в месяц бесплатно без срока. Порядок величин расходов: при единицах пользователей Lambda, API Gateway, DynamoDB и Cognito укладываются в бесплатный уровень или единицы долларов в месяц. Отдельно — Bedrock (за токены), если включим проверку ответов моделью.

### Вход через Google

1. Google Cloud Console: OAuth-клиент типа «Web», redirect URI — домен Cognito `/oauth2/idpresponse`.
2. Cognito: пул пользователей, домен (префикс Cognito или свой), Google как IdP, клиент приложения без секрета, callback — адрес сайта.
3. На сайте: кнопка «Войти через Google» → Hosted UI → код → обмен на токены (PKCE). Access-токен — в памяти страницы; для постоянного входа лучше маленькая Lambda-прослойка (BFF), которая хранит refresh-токен в HttpOnly-cookie, чтобы XSS не мог его украсть.
4. API принимает только access-токен Cognito; идентификатор пользователя — `sub`, email храним только для отображения.

Без входа сайт работает как сейчас, на localStorage. После первого входа локальные отметки объединяются с серверными.

### Данные (DynamoDB, одна таблица)

| PK | SK | Что |
|---|---|---|
| `USER#<sub>` | `PROFILE` | Имя, дата старта плана, настройки |
| `USER#<sub>` | `CARD#c12` | Статус карточки (совместим с `go_prep_progress_v2`) |
| `USER#<sub>` | `PLAN#v1` | Отметки плана (совместимы с `go_prep_plan_v1`) |
| `USER#<sub>` | `ATTEMPT#<время>#<id>` | Попытка: материал, свой ответ до раскрытия, оценка, ревизия контента |
| `USER#<sub>` | `SRS#<id>` | Следующий срок, интервал, сложность (FSRS или SM-2) |
| `USER#<sub>` | `RUN#<время>#<задача>` | Запуск кода: результат тестов, время, без хранения чужих данных |

Экспорт и удаление всех данных пользователя — одной командой API.

Если хочется практиковать SQL на живой базе (недели 5–6 плана: транзакции, outbox), вместо или вместе с DynamoDB можно взять PostgreSQL: RDS (db.t4g.micro — порядка 15–30 $ в месяц с диском) или Aurora Serverless v2. Для самого сайта это избыточно.

## 3. Интерактивные задачи с запуском кода

**Формат задачи** (в репозитории, например `tasks/w3-workerpool/`): условие EN/RU, начальный код, открытые и скрытые тесты, критерий из `PLAN.acceptance`, подсказки по шагам, эталон (не отдаётся в браузер).

**Запуск.** Браузер отправляет код → API → Lambda-раннер: создаёт новый временный каталог, кладёт код и тесты, выполняет `go vet` и `go test -race -count=1 -timeout=10s`, возвращает результат по каждому тесту и обрезанный вывод.

**Безопасность раннера** — главный риск, его закрываем сразу:
- Lambda в VPC без NAT: у кода пользователя нет выхода в интернет;
- IAM-роль без прав; никаких секретов в окружении;
- `-race` требует cgo (`CGO_ENABLED=0 go test -race` → «go: -race requires cgo»), поэтому в образе gcc и `CGO_ENABLED=1`, а `import "C"` в коде пользователя отклоняется; лимиты: память 2 ГБ, время до 25 с (предел интеграции HTTP API — 30 с, не увеличивается), размер вывода и кода;
- новый каталог на каждый запуск и очистка после: тёплые экземпляры Lambda переиспользуются;
- зависимости заранее в образе (кеш модулей), сеть для `go get` не нужна;
- ограничение частоты запусков на пользователя (API Gateway throttling + счётчик в DynamoDB).

Если понадобится более жёсткая изоляция — отдельная задача ECS Fargate на каждый запуск (медленнее старт, 20–60 с).

**Редактор.** Сначала простой `<textarea>` с моноширинным шрифтом (без зависимостей, как сейчас на сайте). Затем — CodeMirror 6 с подсветкой Go, если решим добавить внешнюю зависимость.

**Первая очередь задач:** 11 заданий практикума недель 3–4 (workerpool, pipeline, fanin, counter, safecache, parallelfetch, ratelimit, shutdown, leak, escape, profile) — у них уже есть критерии приёмки. Затем — открытые варианты к карточкам недель 1–2 и задачи «что выведет код».

## 4. Этапы

| Этап | Что | Оценка |
|---|---|---|
| 0 | Аккаунт AWS, бюджет и оповещение, CDK bootstrap, ключ деплоя для GitHub Actions | 0,5 дня |
| 1 | Cognito + Google, кнопка входа, `GET /me`, синхронизация отметок карточек и плана, слияние с localStorage | 2–3 дня |
| 2 | История попыток и интервальное повторение на сервере, очередь «Сегодня» | 3–4 дня |
| 3 | Раннер кода, формат задач, 11 задач практикума, экран задачи на сайте | 4–6 дней |
| 4 | Code review без вариантов, затем проверка ответов на английском через Bedrock (с лимитом расходов) | по готовности |

Сроки — для одного разработчика; этапы 1 и 3 можно вести параллельно.

## 5. Быстрая альтернатива

Supabase (PostgreSQL + вход через Google + Row Level Security) или Firebase дают вход и базу за день без своего API. Минусы: запуск кода всё равно нужен отдельно (та же Lambda или Fly.io), и это не AWS. Если важна скорость — Supabase для входа и данных плюс AWS Lambda только для раннера.

## 6. Что решить пользователю

1. AWS целиком или Supabase для входа и данных + AWS для раннера?
2. DynamoDB или PostgreSQL (нужна ли живая SQL-практика)?
3. Сайт оставить на GitHub Pages или перенести на свой домен (CloudFront)?
4. Только для себя или открыть другим (тогда — лимиты, политика данных, модерация)?
5. Кто ведёт бэкенд: отдельный репозиторий `golang-interview-prep-api` (Go + CDK) — предлагаю так, чтобы не смешивать со статическим сайтом.
