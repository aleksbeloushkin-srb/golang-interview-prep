# Select: что компилируется, что выбирается и где начинается ожидание

Проверено 26 октября 2026 года. Разбор относится к языковому `select` и стандартному компилятору Go: исходники 1.17, 1.25.0 и 1.26.1; исполняемые примеры и листинги — **Go 1.26.1 darwin/arm64**. `reflect.Select`, собственные компиляторы и обещания производительности здесь не рассматриваются.

Главное исправление прежней модели: **`select` не всегда вызывает `runtime.selectgo`**. Сначала компилятор выбирает путь по форме конструкции. Затем готовность конкретных каналов определяет, выполнится ли операция, default, ожидание или panic. Число веток и число уникальных каналов — разные вещи.

## 1. Шесть форм, четыре основных ветви компилятора

| В исходнике | Проверенное преобразование | Что важно |
|---|---|---|
| `select {}` | `runtime.block()` | Парковка горутины навсегда, без активного опроса |
| Только `default` | Выполнить его тело | Нет операций с каналами и вызова `selectgo` |
| Одна отправка или одно чтение | Обычная операция с каналом | Может ждать; nil не становится безопасным |
| Одна операция и `default` | `selectnbsend` или `selectnbrecv` | Неблокирующая проба готовности канала |
| Две и более операции, без `default` | `selectgo(..., block=true)` | При отсутствии готовых — регистрация и парковка |
| Две и более операции и `default` | `selectgo(..., block=false)` | Общий опрос остаётся; при отсутствии готовых — default |

В `walkSelectCases` число `ncas` сначала включает default. Поэтому условие `ncas == 2 && dflt != nil` означает **одну операцию плюс default**, а не две операции плюс default. Нулевой случай, единственная ветка, операция с default и общий путь — четыре основных разветвления кода компилятора. Единственная ветка делится на обычную операцию и только default; общий путь — на разрешённое и запрещённое ожидание.

Схема в sim4 показывает все шесть форм. Важно назвать условие вслух: «две операции с каналами плюс default», а не неоднозначное «две ветки».

## 2. Почему default не означает «вообще не блокируется»

Default позволяет не ждать **готовности операции с каналом**. Но до выбора вычисляются выражения каналов и отправляемых значений; они могут выполнять долгую синхронную работу. Тело выбранной ветки также может ждать. В общем пути runtime использует внутренние блокировки каналов. Поэтому default не является гарантией lock-free исполнения или ограниченного времени всей конструкции.

```go
select {
case out <- build(): // build выполняется до выбора
    // отправка состоялась
default:
    // build уже был вызван, даже если out == nil
}
```

Пустой `select {}` паркует горутину. А бесконечный `for { select { default: } }` может активно расходовать CPU. Это противоположные случаи. Если в отдельной программе после `select {}` некому продолжить работу, runtime может сообщить fatal deadlock. Из парковки одной горутины нельзя заключать, что любая программа немедленно завершится: в ней может оставаться другая работа.

## 3. Два результата чтения: selected и ok

В специализированном пути `selectnbrecv` возвращает `(selected, received)`. Первый результат выбирает тело case вместо default. Второй становится `ok` в Go-коде.

| Канал | selected | received / ok | Результат |
|---|---|---|---|
| nil | false | false | default |
| Открытый пустой, нет отправителя | false | false | default |
| Есть отправленное значение, включая 0 | true | true | case с этим значением |
| Закрыт, но буфер ещё содержит значение | true | true | case со следующим значением |
| Закрыт и опустошён | true | false | case с нулевым значением типа |

**«Выбрано чтение» не равно «получено ранее отправленное значение».** Новая q22 проверяет это различие. Закрытый канал в цикле остаётся готовым: если по `ok=false` не выйти или не отключить ветку присваиванием переменной канала в nil, цикл может крутиться. При отключении надо отдельно решить, когда завершать весь цикл, иначе все оставшиеся nil без default дадут вечное ожидание.

Для отправки helper возвращает один флаг выбора. Отправка в закрытый канал вызывает panic, если выбрана эта операция. Единственная закрытая отправка плюс default паникует; default её не «страхует». Если рядом есть другое готовое чтение, может быть выбрано оно — panic не обязательна при каждом запуске.

## 4. Общий selectgo: три прохода, не три захвата блокировок

1. Компилятор готовит массив операций. Отправки размещаются с начала массива, чтения — с конца. Default не является элементом массива операций.
2. Runtime исключает nil-каналы из порядков опроса и блокировок. Это не повторная компиляция: две операции, одна из которых получила nil, по-прежнему идут по общему пути.
3. `pollorder` задаёт случайный опрос. `lockorder` задаёт согласованный порядок блокировки уникальных каналов по адресам, чтобы два select не захватывали их в противоположной последовательности.
4. Под блокировками первый проход ищет готовую операцию. Если она найдена, выполняет её и возвращает результат. Если нет, но есть default, отпускает блокировки и возвращает `chosen=-1`.
5. Если готовых нет и ожидание разрешено, второй проход под **теми же блокировками** регистрирует sudog для активных веток. Парковка через `gopark` / `selparkcommit` отпускает блокировки.
6. Конкурирующие операции пытаются забрать ожидание через `selectDone.CompareAndSwap(0, 1)`. Победитель передаёт данные или сообщает закрытие и делает G готовой к запуску. Готовность не обещает немедленного исполнения.
7. После возобновления третий проход снова захватывает набор каналов, удаляет оставшиеся регистрации и освобождает sudog. Затем отпускает блокировки и возвращает выбор.

В показанном обычном пути с парковкой набор каналов захватывается **дважды**: для опроса/регистрации, затем для очистки. Пути готовой операции и default не проходят всю эту последовательность.

Две ветки с одним каналом — две отдельные кандидатуры. Мьютекс этого канала захватывается один раз, но готовые ветки не сливаются в одну. Равновероятный выбор относится к готовым операциям, а не к уникальным каналам. Не стоит выводить из него фиксированный порядок, максимальное время ожидания или статистическую гарантию на маленьком числе запусков.

## 5. Внутренний индекс и номер ветки — разные вещи

Для исходных чтений `A, B, C` массив компилятора получается `scases = [C, B, A]`. Пример случайного опроса `[1, 0, 2]` означает `B, C, A`. Если победила C, runtime возвращает внутренний `chosen=0`, а компилятор выполняет **третью** ветку исходника.

В старой sim4 запись `case 2` одновременно изображала исходную ветку и внутренний индекс. Это было неточно. Теперь показано явное соответствие. Адреса каналов в схеме условные; исход W1/W2 выбран для объяснения, а не получен инструментальной трассировкой.

## 6. Порядок вычислений: до и после выбора

При входе в select один раз, в порядке исходника, вычисляются:

- операнды каналов для отправок и чтений;
- правые части отправок `ch <- expression`.

Это происходит независимо от того, какая ветка будет выбрана. Nil-канал, default и уже закрытый `ctx.Done()` не отменяют эти вычисления. Если выражение паникует или не возвращается, до выбора операции дело не дойдёт.

После выбранного чтения вычисляется левая часть присваивания, например `dst[index()]` в `case dst[index()] = <-ch:`. Затем значение присваивается, выполняется тело case. При выборе default `index()` из ветки чтения не вызывается.

Исправленная q17 — самостоятельная детерминированная программа: буфер заполнен, done закрыт, но build всё равно увеличивает счётчик. Вывод `cancelled`, затем `1`. Прежний текст ошибочно привязывал языковое правило к обязательному вызову `selectgo` и объявлял любую полученную из БД задачу потерянной. Фактическая сохранность зависит от резервирования, транзакции и подтверждения обработки.

Для отменяемой подготовки context нужен внутри самой долгой операции. Предварительная проверка `ctx.Err()` обнаруживает уже видимую отмену, но отмена может случиться сразу после проверки. Порядок case не даёт строгого приоритета. Это сохраняется и после оптимизаций компилятора.

## 7. Что различается между версиями

| Версия | Что проверено | Вывод |
|---|---|---|
| Go 1.17 | Исходник `walk/select.go` | Уже есть пустой, единичный, операция+default и общий пути. Внутренние API компилятора отличаются |
| Go 1.25.0 | Исходник того же файла | Для рассматриваемой классификации нет отличий от 1.26.1 |
| Go 1.26.1 | Исходник + компиляция 14 функций на darwin/arm64 + тесты семантики | Файл `walk/select.go` побайтно совпадает с проверенным 1.25.0; реальные вызовы подтверждены листингом |

Это не утверждение, что весь compiler/runtime одинаков между версиями. Старые toolchain не запускались. На текущей публичной странице спецификации может отображаться более новая версия; для сверки 1.26 использована также локальная `doc/go_spec.html` установленного релиза.

Примеры вызовов в листинге 1.26.1 (`go tool compile -S -l`):

| Функция-пример | Вызов runtime, кроме служебного morestack |
|---|---|
| `select {}` | `block` |
| Только default | Нет |
| Единственная отправка | `chansend1` |
| Единственное чтение с отброшенным результатом | `chanrecv1` |
| Единственное `case v := <-ch` в проверенном примере | `chanrecv2` |
| Единственное чтение с ok | `chanrecv2` |
| Отправка + default | `selectnbsend` |
| Чтение + default | `selectnbrecv` |
| Две операции, с default или без | `selectgo` |

Не нужно заучивать неверное правило «нет ok в исходнике — обязательно chanrecv1»: преобразование select может сохранить форму чтения с двумя результатами, даже если один дальше не используется. Имена helper — уровень реализации; ответ на интервью сначала должен описывать семантику.

## 8. Как закреплять

Опора **«форма → готовность → ожидание»** помогает восстановить порядок рассуждения. Это учебная подсказка, её эффект на нашем сайте ещё не измерен.

1. Закрой схему и классифицируй шесть форм: сколько операций, есть ли default, какой путь?
2. Измени одно условие: добавь вторую операцию; сделай канал nil; закрой его; оставь в буфере 7. Предскажи результат до запуска.
3. Раздели вопросы: «выбран ли case?» и «чему равен ok?».
4. Восстанови цепочку общего пути, сначала без имён функций: проверить → зарегистрировать → уснуть → один победитель → убрать лишние записи → вернуться в исходную ветку.
5. Скажи по-английски: “The compiler specializes simple selects. With multiple channel cases it uses selectgo; default disables waiting when no operation is ready.” Затем добавь собственный пример.
6. Вернись к q17/q22 позже без подсказки. Отдельно отметь ошибку механизма и трудность объяснения на английском. Успешное перечитывание сразу после ответа ещё не показывает долговременное запоминание.

Автоматического расписания и записи таких попыток пока нет. Общий анализ и план — [LEARNING_DESIGN_RU.md](LEARNING_DESIGN_RU.md).
