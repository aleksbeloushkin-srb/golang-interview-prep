Владелец готовится к собеседованиям Senior Go в европейских компаниях (интервью на английском; опыт — Java и Kotlin). План — 13 недель с 12.10.2026. ## 3. Что сделать

**Шаг A — короткое предложение (до 1 страницы, в описании PR).** Какие механизмы, формат данных, где в интерфейсе, что сознательно не делаешь. Без ссылок на «нейрохаки» и без обещаний эффекта: ссылайся на практики из `LEARNING_DESIGN_RU.md`.

**Шаг B — прототип в ветке `google/memory-<тема>`, по приоритету:**

| № | Что | Готово, когда |
|---|---|---|
| P1 | **Журнал попыток и резервная копия.** Новый ключ `go_prep_attempts_v1`: `{ itemId, kind: card / sim-check / sim-predict / quiz / plan-model, ts (ISO), mode: recall / with-hint, grade: again / hard / good / easy, lang: en / ru, rev }`. Кнопки «Экспорт» (JSON-файл) и «Импорт» (проверка формата, слияние без дублей) | Старые ключи `go_prep_progress_v2` и `go_prep_plan_v1` не меняются; повреждённый JSON и недоступный localStorage не ломают сайт; импорт своего же экспорта ничего не дублирует |
| P2 | **Очередь «Сегодня».** Простые интервалы по оценке (например, 1 → 3 → 7 → 16 → 35 дней; again — снова сегодня), сессия до 10 единиц, смешивание карточек, вопросов шагов диаграмм и quiz только из пройденных недель плана. Сначала вопрос без ответа, затем «Показать», затем оценка | Граница дня — по местному времени (Europe/Belgrade); после перезагрузки сессия продолжается; прежние `mastered` становятся только начальной самооценкой (срок через 3 дня), без выдуманных прошлых повторений; никаких серий и штрафов за пропуск |
| P3 | **«Скажи вслух».** Для `modelAnswers` и `shortEN` карточек: показать вопрос и `hook`, по желанию таймер 60 с, затем эталон EN и самооценка. Вариант «пропуски»: скрыть 3–5 ключевых терминов эталона | Работает с клавиатуры и на телефоне 390 px; таймер не обязателен и уважает `prefers-reduced-motion` |
| P4 | **Quiz без вариантов.** Сначала свой ответ (что выведет программа), потом варианты | Переключатель режима; запоминается в localStorage как удобство |
| P5 | **Пилот малых единиц.** Для 5 больших карточек недель 1–3 предложи по 2–4 коротких вопроса на воспроизведение (`prompts`). Содержание — только с источниками (спецификация Go, go.dev, исходники с тегом версии) | Каждая формулировка проверена по источнику; EN и RU говорят одно и то же |

P1 и P2 — главное. P5 — содержание; его потом редактирует Астра.

## 4. Ограничения

- Статический сайт без сборки и внешних зависимостей: HTML, CSS, JS. Порядок скриптов и глобальные точки входа (`renderSimStep`, `CARDS`, `SIMULATORS`, `QUIZ_QUESTIONS`, `PLAN`) не менять. Пользовательский текст — через `textContent`.
- ID карточек, задач, шагов и задач плана стабильны. Формат журнала сделай пригодным для будущего сервера (AWS, см. `AWS_RECIPE_RU.md`, этап 3): простой JSON, время ISO, стабильные ID.
- Не меняй техническое содержание карточек и диаграмм, кроме P5. Если видишь ошибку — опиши её в отчёте.
- Markdown в репозитории проходит через Jekyll/Liquid на GitHub Pages: двойные фигурные скобки и сочетание фигурной скобки с процентом вне блока raw ломают сборку. Проверка: `node scripts/check-content.mjs`.
- Чужие журналы не трогай: `CHANGE_LOG_RU.md`, `CURRENT_STATUS_RU.md` (Астра), `CLAUDE_*.md` (Claude). Свой журнал — `GOOGLE_CHANGE_LOG_RU.md`: что, зачем, где, как проверено, ограничения.
- Только своя ветка и PR. Merge — решение владельца.

## 5. Проверка перед PR

1. `node scripts/check-content.mjs --base origin/main` и `node --test scripts/check-content.test.mjs` — без ошибок.
2. `node --check` для каждого изменённого JS-файла.
3. Браузер на 390 и 1280 px: новый раздел, `#/cards`, `#/plan`, `#/simulators/sim3`, `#/quiz/q22`; клавиатура и видимый фокус; без горизонтальной прокрутки; без ошибок в консоли.
4. Сценарии хранения: перезагрузка сохраняет очередь и журнал; localStorage недоступен; импорт повреждённого файла; импорт своего экспорта дважды.
5. В отчёте — только реально выполненные проверки.
